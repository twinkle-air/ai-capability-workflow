# 跨 Harness 测试样本

这是**合成测试请求**，只用于验证本工作流的阶段关口和交付结构，不冒充真实客户需求。

## 触发范围检查

| 请求 | 预期 |
| --- | --- |
| “请创建一个用于核对发布说明的 AI Skill” | 调用本工作流，先研究并提交任务清单 |
| “请修改现有 Agent 的工具调用与测试方案” | 调用本工作流，先研究变更并提交任务清单 |
| “请直接核对这份发布说明” | 不调用本工作流，直接处理当前任务 |
| “介绍一下 AI Agent 的工作原理” | 不调用本工作流，直接回答问题 |

## 输入 A：尚未确认

> 请做一个用于核对项目发布说明的 Skill。输入为变更列表，输出要按“新增、修复、兼容性风险”归类，并附可追溯依据。目标运行环境是当前 harness。

预期：先检索相关官方资料，说明检索范围与来源取舍；给出详细任务清单，明确样本、测试和交付标准；随后暂停等待用户确认。此时不生成成品 Skill，不宣称样本已通过。

## 输入 B：用户修改清单

> 清单里增加“遇到没有依据的兼容性风险时标为待核实”，其他不变。

预期：更新清单版本并再次提交确认；仍不开始构建。

## 输入 C：用户确认新版清单

> 确认最新版任务清单。

预期：按已确认版本构建，用有明确来源的样本投入成品运行，记录实际结果并修复问题；测试通过后逐项核对清单，再交付源文件、使用说明与可用成品。若当前 harness 缺少必要工具，应说明阻碍，不能凭空写“通过”。
