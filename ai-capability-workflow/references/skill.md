# Skill 设计要点

适用于现有助手在特定请求中需要额外指导或资源的情况。

1. 用名称和描述表达“做什么、何时用”，使调用边界可识别；避免“处理所有 AI 任务”之类宽泛描述。
2. 主文件只写共同目标、关键约束与资源入口。把只在特定模式需要的长说明放入参考文件，按需读取。
3. 脚本只用于需要重复执行或确定性保证的逻辑；素材只保留交付时确实会用到的文件。
4. 用相近请求和反例检查触发是否准确；用真实任务检查指令是否改变了实际行为。
5. 平台专有的目录、元数据与校验命令，按目标平台的当前规范实现。Codex 的 Skill 需要带 `name`、`description` 的 `SKILL.md`；若使用 Codex bundled skill-creator，可运行其 `quick_validate.py` 做结构校验，但还须检查实际行为。
